# Loot Bans Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add persistent, realm-scoped Loot Bans that leave players and rolls visible while preventing every managed loot award and exposing the ban note through RaidGrid and Attendance tooltips.

**Architecture:** `Services.Raid.LootBans` owns the optional `RMA_Players[realm][name].lootBan` record and emits one internal change event. Rolls consume that owner as an eligibility policy, the award path repeats the check immediately before execution, and the Master and Attendance controllers render the same current-state projection without duplicating persistence logic.

**Tech Stack:** World of Warcraft 3.3.5a build 12340, Interface `30300`, Lua 5.1.5, FrameXML, Python 3 `unittest`, PowerShell repository validators.

## Global Constraints

- Preserve addon name `Raid Management Addon`, runtime short name `RMA`, `/rma`, `RMA_*` SavedVariables, and `RMA` addon-message prefixes.
- Store Loot Bans only as optional metadata under the existing `RMA_Players`; add no SavedVariable, non-RMA migration, or wire-format field.
- Keep runtime Lua 5.1-compatible and use only WotLK 3.3.5a APIs.
- Keep XML layout-only; Lua owns callbacks, popup behavior, tooltips, refreshes, and visibility.
- Keep all new runtime strings and comments ASCII and route user-facing copy through `addon.L`.
- Do not modify vendored files under `Libs/`.
- The note limit is exactly 240 ASCII characters; whitespace-only notes normalize to `nil`, and over-limit notes are rejected rather than truncated.
- A banned roll remains visible as existing status `INELIGIBLE` / tag `BLK`, with reason `LOOT_BAN`.
- Attendance displays current ban state, including historical raid views; it does not persist per-raid ban snapshots.
- Do not include the pre-existing root or addon README edits in feature commits unless the user separately asks for them.

- [ ] **Step 4: Implement the minimal canonical owner**

Create `Services/Raid/LootBans.lua` with this public shape and no UI dependencies:

```lua
local addon = select(2, ...)
local Database = addon.Database
local Services = addon.Services
local Strings = addon.Strings
local Bus = addon.Bus
local InternalEvents = addon.Events.Internal
local type = type
local strlen = string.len

local Raid = assert(Services.Raid, "Raid service namespace is not initialized")
Raid.LootBans = Raid.LootBans or {}
local LootBans = Raid.LootBans
local NOTE_MAX_LENGTH = 240

local function getPlayerRecord(playerName, create)
    local realm = Database.GetRealmName()
    local name = Strings.NormalizeName(playerName, true)
    local players = Database.SavedVariables.GetPlayers()
    if not realm or realm == "" or not name or name == "" then
        return nil, name
    end
    if create then
        players[realm] = players[realm] or {}
        players[realm][name] = players[realm][name] or {}
    end
    return players[realm] and players[realm][name] or nil, name
end

function LootBans.ValidateNote(note)
    local clean = Strings.TrimText(note, true)
    if clean == "" then
        return nil
    end
    if strlen(clean) > NOTE_MAX_LENGTH then
        return nil, "note_too_long"
    end
    return clean
end

function LootBans.Get(playerName)
    local player = getPlayerRecord(playerName, false)
    local ban = player and player.lootBan
    if type(ban) ~= "table" or ban.active ~= true then
        return false, nil
    end
    local note = type(ban.note) == "string" and ban.note or nil
    return true, note
end

function LootBans.IsActive(playerName)
    return LootBans.Get(playerName) == true
end

function LootBans.Set(playerName, note)
    local cleanNote, err = LootBans.ValidateNote(note)
    if err then
        return nil, err
    end
    local player, name = getPlayerRecord(playerName, true)
    if not player then
        return nil, "invalid_player"
    end
    player.lootBan = { active = true, note = cleanNote }
    Bus.TriggerEvent(InternalEvents.LootBansChanged, name, true, cleanNote)
    return true
end

function LootBans.Remove(playerName)
    local player, name = getPlayerRecord(playerName, false)
    if not player or player.lootBan == nil then
        return false
    end
    player.lootBan = nil
    Bus.TriggerEvent(InternalEvents.LootBansChanged, name, false, nil)
    return true
end

return LootBans
```
